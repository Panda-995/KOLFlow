# v1.4.7 发布验证报告

问题来源：v1.4.6 绿联包在用户 NAS 上出现 `SQLITE_CANTOPEN` 并持续重启；同一版本镜像经普通 Docker Compose 可以启动。镜像站 latest 与固定 1.4.6 的清单摘要相同，因此差异集中在绿联包挂载的数据目录及其权限。用户设备实际挂载路径尚未提供，本次以合成目录和容器权限模拟复现。

修复：启动入口先检测数据目录、SQLite 及 WAL/SHM 文件、上传目录的实际读写能力。目录拒绝 chown 时尝试以实际所有者身份运行；绿联包配置允许在该身份仍不可用、但容器管理员可写时回退。所有身份均不可写时给出明确错误，不再只有 SQLite 堆栈。普通 Docker 保留非管理员默认与可配置的管理员回退。绿联包同时声明可在应用设置中授权共享目录。

云端原生 amd64/arm64 测试将检查：原有数据升级与重启、自定义目录、目录所有者 UID 2000 且 chown 被拒绝、仅容器管理员可写且 chown 被拒绝、完全不可写时的错误提示，以及宿主端口 3441 的 HTTP 页面和健康接口。测试不等于 NAS 真机验证。
