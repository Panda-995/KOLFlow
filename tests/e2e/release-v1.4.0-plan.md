# KOLFlow v1.4.0 端到端测试计划

## 目标与环境

- 目标：验证商单模板、周期数据通知、旧数据兼容和既有核心页面在生产构建下可用。
- 环境：本机 Chromium，独立 SQLite 数据目录，生产模式静态资源与真实 Express API。
- 证据：HTML 报告；失败时保留截图、视频和 Playwright trace。

## 用例

| ID | 优先级 | 场景 | 关键步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| E2E-01 | P0 | 注册与登录态 | 首次注册并同意隐私政策 | 进入仪表盘，刷新后会话仍有效 |
| E2E-02 | P0 | 商单模板完整流程 | 新建模板、编辑、一键创建两次、删除模板 | 模板字段可维护；两个商单号不同；每次都创建待办；删除模板不删除商单 |
| E2E-03 | P0 | 周报通知有真实数据 | 完成模板商单、添加推广费、开启周报、刷新并打开通知 | 显示报告日期、完成数、待收金额和推广费，不出现空通知 |
| E2E-04 | P0 | 周报精确跳转 | 点击周报通知 | 进入含 period/start/end 的统计地址；页面显示同一周期和对应数据 |
| E2E-05 | P1 | 旧数据兼容 | 导入不含 orderTemplates 的 v2 备份 | 导入成功；旧商单可读；模板集合为空且系统仍可继续创建模板 |
| E2E-06 | P1 | 核心页面冒烟 | 依次打开仪表盘、商单、账单、Todo、品牌、资产库、统计、日志、设置 | 路由、页面标题和 API 请求正常，无页面异常 |

## 定位与通过标准

- 优先使用角色、可见名称、表单标签和 URL；仅在没有稳定语义时使用结构定位。
- P0 必须全部通过；P1 不得出现阻断性错误。
- 同时要求单元/集成测试、TypeScript 检查、Web 构建、服务端构建全部通过。
- 旧数据兼容由真实导入 API 与回归测试双重校验；模板缺失按空集合处理，不修改旧字段含义。
